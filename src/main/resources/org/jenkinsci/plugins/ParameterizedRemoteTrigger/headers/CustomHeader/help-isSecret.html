When enabled, the header value will be treated as sensitive data:
  • Encryption at Rest: The value will be encrypted in Jenkins configuration files using Jenkins' built-in hudson.util.Secret mechanism
  • Log Masking: Jenkins will automatically mask the value in console output and build logs
  • Security Best Practice: Always enable this for sensitive values like API keys, tokens, passwords, or other credentials

Example Use Cases for Secret Headers:

  • API keys: X-API-Key
  • Access tokens: X-Access-Token
  • Custom authentication headers

Note: Even with this option enabled, use proper Jenkins credential management (Credentials Plugin) for highly sensitive authentication data when possible.
